# Maintenance & Governance

이 문서는 로컬 CSV 배치와 오프라인 모니터링의 유지보수 절차를 정의한다. 현재 상태와 검증 결과는 [프로젝트 진행 기록](project-status.md)에서 관리한다.

## Versioning and Recovery

- 코드의 Git 커밋과 패키지 버전, 모델 ZIP의 `model_version`과 `format_version`을 구분한다. 모델을 교체할 때는 별도 ZIP 경로를 사용하고 이전 ZIP과 당시 실행 환경을 함께 보관한다.
- 모델 변경 기록에 코드 커밋, 패키지·Python 버전, `uv.lock`, 모델 ZIP 이름과 SHA-256, 학습 데이터의 출처·기간과 검증 결과를 남긴다. 데이터와 ZIP은 접근을 제한한 저장 위치에 두고 인계 시 복구 위치를 전달한다.
- 배치 실행 기록에는 입력을 다시 식별할 수 있는 배치 ID, 모델 버전, 실행 결과와 출력 위치를 남긴다. 이전 결과는 모델 버전과 배치 ID로 구분한다. 복구 시 호환 환경에서 이전 ZIP을 `--model`로 지정하고 같은 입력을 별도 결과 경로로 처리한다.

## Data and Artifact Handling

- 원본 데이터, 운영 입력과 라벨, 점수 CSV, 모델 ZIP, 비밀값은 Git 외부에서 관리한다. 로컬 생성 결과는 Git에서 제외된 `artifacts/` 등에 저장하고, 커밋 전에 스테이징된 파일을 확인한다.
- 배치에 필요한 19개 입력만 전달한다. 라벨을 연결하는 경우 배치 ID와 레코드 키의 대응표를 접근이 제한된 위치에 보관한다. 공유 점검 기록에는 집계나 합성 예시를 사용한다. 실제 데이터를 받기 전에 접근 권한, 보존 기간과 삭제 책임자를 정한다.
- 직접 생성했거나 출처를 확인한 ZIP만 로딩한다. ZIP 안의 pickle은 로딩 시 코드를 실행할 수 있다. 체크섬은 알려진 파일과의 일치 여부를 확인하며, 출처 확인은 별도로 한다.

## Dependency and Release Checks

코드나 의존성을 변경할 때 다음 검사를 실행하고 결과를 변경 기록에 남긴다.

```bash
uv lock --check
uv run --locked pytest
uv run --locked ruff check .
git diff --check
```

- 의존성 변경을 검토할 때 릴리스 노트와 보안 공지를 확인한다. 변경 이유, 영향 범위, 호환성 확인 결과를 기록하고 `pyproject.toml`과 `uv.lock`을 함께 검토한다.
- 모델 로더는 저장 시의 Python과 주요 패키지 버전이 실행 환경과 일치하는지 검사한다. 런타임 변경 전 후보 환경에서 승인된 ZIP의 로딩과 합성 입력 CLI 실행을 확인한다. 호환되지 않으면 기존 환경을 보존하고 새 환경에서 별도로 검증한 모델의 전환을 검토한다.
- 로컬 호환 ZIP이 있으면 [오프라인 모니터링](../README.md#offline-monitoring)으로 정상, 실패, 복구 흐름을 확인한다. CLI 출력 계약이나 모델 버전을 바꾸면 기존 사용 절차와 롤백도 점검한다.

## Handoff and Review

- 인계 시 실행 명령, 현재 모델의 버전과 복구 위치, 환경 재현 방법, 마지막 검증 결과와 열린 과제를 전달한다.
- 배치 오류와 데이터 변화는 10단계 점검 기준을 적용한다. 신규 라벨이 확보되면 11단계 절차로 비교 범위와 교체 기준을 정하고, 새 기간에서 후보를 검증한다. 6단계의 Test 결과는 확정 평가 기록으로 보존한다.
- 실제 운영 도입 전에는 입력의 예측 시점 가용성, 라벨 관측 범위, 업무 연락 용량, 데이터 보존·접근 책임을 확인한다.
